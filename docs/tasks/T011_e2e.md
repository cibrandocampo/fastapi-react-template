# T011 — End-to-end tests

**Plan**: docs/plans/template-base.md · **Depends on**: T010

## Objective
Playwright drives the production image (app + db + mailpit) through the real user flows, OTP included.

## Step 1 — Stack
`e2e/docker-compose.yml`: app built from the root `Dockerfile` with `ALLOW_SELF_SIGNUP=true`,
`COOKIE_SECURE=false`, `RATE_LIMIT_ENABLED=false`, admin from env, SMTP to mailpit; db; mailpit;
`playwright` service (`e2e/Dockerfile`, official Playwright image) with the specs. `make e2e` builds,
runs the specs, tears everything down and keeps the report in `e2e/playwright-report/`.

## Step 2 — Specs (`e2e/tests/`)
Helpers: read the latest code for an address from Mailpit's API; log in as admin.
- sign-up with OTP → onboarding name → waiting page
- admin grants access → the user now reaches home
- password login, wrong password message, lockout message
- profile: language change persists after reload; theme persists; set password then log in with it
- admin users page: create, deactivate (user can no longer log in), last-admin guard message
- logout, and protected route redirects when anonymous; session survives a reload (refresh cookie)

## DoD
1. `make e2e` passes three times in a row without retries.
2. No `test.skip`, no fixed sleeps (wait on UI state or Mailpit polling with timeout).

## Implementation notes
- `e2e/docker-compose.yml`: `server` (the production image from the root Dockerfile, read-only,
  `ENV=production`, sign-up on, rate limits off, SMTP to Mailpit, admin from env, fixed test secret),
  `db` (Postgres on tmpfs), `mailpit`, `playwright` (`e2e/Dockerfile`, image
  `mcr.microsoft.com/playwright:v1.65.1-noble`, `@playwright/test` 1.65.1 pinned with a lockfile).
  The app service is called `server`, not `app`: Chromium preloads HSTS for the whole `.app` TLD, so
  `http://app` is always forced to https (`ERR_SSL_PROTOCOL_ERROR`).
- `make e2e` creates `e2e/artifacts`, builds, `run --rm playwright` (dependencies wait for health),
  always `down -v`, and exits with the runner's status. HTML report in `e2e/artifacts/report`, traces and
  screenshots of failures in `e2e/artifacts/test-results` (git-ignored, owned by the host user).
- `global-setup.js` completes the env admin's onboarding once (it has no name), so no spec depends on the
  order of the others. Specs run one at a time (shared admin, last-admin guard); each creates its own
  accounts with unique emails.
- Helpers: Mailpit polling (`expect.poll`, 15 s) for the code of an email that was not there before the
  request; log in with code / password / as admin; sign up; create a user and grant access from the
  admin page.
- Specs (14): sign-up → onboarding → waiting; grant access → home; anonymous redirect and return to the
  requested page; session survives reload; logout then protected route; password login; wrong password;
  lockout after 5 failures even with the right password; language and colour scheme saved on the account
  (checked from a fresh browser, not just after reload); OTP account sets a password and signs in with
  it; admin creates a user; deactivated user cannot sign in; last-admin guard.
- No `test.skip`/`only`, no `waitForTimeout`, no `force: true` (hidden inputs are used as people do:
  the segmented control's label, the switch from the keyboard). `actionTimeout`/`navigationTimeout` 15 s.
- `make lint-e2e` (part of `make lint`): Prettier with the frontend config, in Docker.
- Evidence: `e2e_1.txt`–`e2e_3.txt` (14 passed each, no retries, ~1 min), `patterns.txt`,
  `lint-e2e.txt`.

### Observations        (non-blocking)
- **O1**: `Makefile` `e2e` — an interrupted run (Ctrl-C during `run`) skips `down -v` (no trap), leaving the
  stack up; a failed `build` is harmless (nothing started).
- **O2**: The plan said `e2e/playwright-report/`; the report is at `e2e/artifacts/report` (documented in the
  implementation notes, git-ignored). The now-unused `playwright-report/` line in `.gitignore` predates this task.
- **O3**: `e2e/` has no `.dockerignore`, so `e2e/artifacts/` (report, traces) is sent as build context of the
  `playwright` image; negligible today.
- **O4**: `helpers.js` `messagesTo` checks `expect(response.ok()).toBeTruthy()`; a status assertion would give a
  clearer failure, the behaviour is the same.
- QA O1–O4 fixed after approval: `trap … EXIT INT TERM` tears the stack down on Ctrl-C and keeps the status (checked: `e2e_trap.txt`, 14 passed, no containers left; a failing command still exits 3 after the trap); `e2e/.dockerignore`; Mailpit check asserts the status; stale `playwright-report/` ignore removed.
